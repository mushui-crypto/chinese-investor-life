# 伙食反馈与界面分隔

本次使用 impeccable 的 product 与 layout 指引整理生活费弹窗和共享生活、结算区块，保留游戏已有的纸色、深绿、字体与按钮样式。

## 欠费与缺食

实际存档在 2006-07-06 连续欠费 33 天，每日开销 ¥88、预计日工资 ¥82.66。上次工资先付了 ¥20 伙食，剩余 ¥5.34 形成欠款，因此连续缺食为 0，饥饿健康损失为 0。不是连续 33 天没有吃饭。

- 弹窗与生活侧栏常驻显示「连续欠费」和「连续缺食」，零值也显示。
- 健康区直接显示上次伙食实付 / 所需金额、缺食扣健康，不再把实际结果藏在折叠规则里。
- 结算单保存本次推进中最近一天的伙食结果；之后吃饭不会改写旧结算。没有结算一天时不显示旧日伙食作为本次结果。旧存档缺少此字段仍可加载。
- 保持按实际缺食扣健康：完全缺食每天 −10、部分不足按比例扣减。吃够一天清零连续缺食，但不恢复健康或免除欠款。

## 统一的分隔规则

- 同一交界只画一条线，由后一个区块的顶边负责。移除开销概览底边、健康区底边及叠加的下外边距。
- 主要区块使用共享 `--content-rule`；操作列表使用同色弱化的 `--content-rule-soft`。
- 生活费弹窗、侧栏、阶段结算与底部生活安排共用内容分隔、区块间距及行间距。分割线不用于替代按钮外框。
- 简化直接过一天的说明，避免与健康区重复解释；规则仍可展开查看。
- 窄屏操作重排为上下布局，保留 44px 按钮目标，弹窗内部滚动。

## 验证

- 回归覆盖连续四天缺食、部分缺食、重新吃饭、健康到就医线、读档后继续扣除，以及已付伙食的连续欠费。
- 桌面及 390px 宽度检查：主要区块无横向溢出；健康区与结算入口交界只有一条 1px 分割线；底部操作滚动可达。
- 验证过程中保留原存档日期、现金、健康和欠款，没有替玩家结算或借款。
