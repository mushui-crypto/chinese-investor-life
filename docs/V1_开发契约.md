# v1.0 开发契约

目标：浏览器单机完整人生游戏；0–80 岁、12 种随机家庭、180 个事件池、24 结局、时代乱流与历史回放、所有已列市场与生存路线、存档/导出导入、图鉴与人生记录、桌面/手机适配。金融机制为虚构游戏模型。根开发整合 UI，engine 代理只改 core.js/core.test.js，narrative 代理只改 narrative.js/narrative.test.js，art 代理只改 public/assets 与美术说明。

技术：原生 ES modules + HTML/CSS，Node 22 原生测试和静态服务器，无需第三方生产依赖。所有金额为安全整数分，使用 Math.round 的整数运算，每次操作校验 Number.isSafeInteger；结果不得静默溢出，超上限拒绝操作。数据目录保留既有剧本。

## Core 接口

src/game/core.js 导出：
- createState({family, seed, name, mode='remix', birthYear=1988}) -> state。seed 为字符串可哈希；family 为完整 data/families 对象。
- applyAction(state, action) -> {state, result}；非法操作返回原状态与 result.error，不抛异常给 UI。result:{title,text,changes?:[{label,value}],error?:string}。
- applyEffects(state, effects, context={eventId,profile}) -> {state,result}；原子应用事件效果，失败不部分提交。
- advanceTurn(state, shock=null) -> {state,result}；推进时间、工资生活费、利息、持仓等，只一次。
- getMetrics(state) -> {cash,assets,debt,netWorth,availableCash,monthlyIncome,monthlyExpense,...ending snake_case yuan metrics}；前7项金额为分，结局 _yuan 字段为元。
- getEligibility(state,key) -> boolean，getActionAvailability(state,action)->{allowed,reason}。
- random(state) -> [value0to1,newState] 或另提供 rngNext(seedNumber) -> {value,seed}（代理须报告选项）。

state 固定字段：version:1, id, name, seed(初始字符串), rng(整数状态), familyId, familyName, familyReserve(分), adultGift(分), giftReceived:boolean, mode:'remix'|'history', birthYear, age(数值支持.5), turn(整数), cash(分), stats:{health,stress,skill,insight,trust,fame,credit}, flags:{key:boolean}, positions:[], debts:[], claims:[], businesses:[], relationships:{npcId:number}, household:{partner:boolean,hasChild:boolean,livingParent:boolean}, occupation:string, monthlyIncome(分), actionPoints(每回合2), logs:[], ledger:[], netWorthHistory:[], peakNetWorth(分), wipeouts, debtFreeTurns。

positions 通用：id,name,kind,cost,value(分),lockUntilTurn,可选 underlying,units,entryPrice,expiryTurn,margin,leverage,direction,liquidation,frozen。
debts 通用：id,name,principal(剩余本金分),interest(分),aprBps,monthsLeft,purpose,overdue。claims:{id,name,face,value(分)}。businesses:{id,name,value,monthlyProfit(分)}。

日志统一 {id,turn,age,title,text,kind:'story'|'income'|'loss'|'system',...}。root UI 只读取字段。

动作：{type:'work'|'gig'|'study'|'rest'|'social'|'seek_job'|'business_start'|'business_run'|'borrow'|'repay'|'invest'|'sell'|'claim'|'relationship'|'exit_risk',...}。
invest:{product:'stock'|'fund'|'bond'|'option'|'option_short'|'futures'|'crypto'|'ponzi'|'angel'|'housing',amount:分,direction:'long'|'short',leverage:2|5|10}。borrow:{kind:'bank'|'net'|'family',amount:分}。repay:{amount:分}。sell/claim:{id}。relationship:{kind:'partner'|'child'|'repair'|'succession'}。

每个实际行动消耗1行动点，借款/出售/还款也有限次数，不能无限刷同回合。事件效果不消耗行动点。未成年只能study/rest/social（以及剧情指定非成人选项）。成年人零钱可以免费work/gig/seek_job/rest/social。先防双扣款再考虑爽感。

Core 不导入 narrative，保证无环。不得改 root UI 和 package 文件。

## Narrative 接口

src/game/narrative.js 导出：
- createRun(options,catalog) -> state，自动选择随机或 options.familyId 指定家庭，调用core.createState，注册出生事件。
- chooseEvent(state,eventId,choiceId,catalog) -> state，校验当前事件，选择已确定的结果，调用applyEffects。state.lastResult 保存供UI反馈，phase='result'。
- continueStory(state,catalog) -> state，处理待展示事件否则进入planning，80岁归档进ended。
- act(state,action,catalog) -> state，调用core.applyAction，反馈供UI；非法不扣回合。
- nextTurn(state,catalog) -> state，调用core.advanceTurn，随后按阶段挑事件，不丢主线。
- eligibleChoices(state,event) -> [{...choice,disabled,reason}]。
- evaluateEndings(state,catalog) -> [{...ending}]，按priority排序，兜底。
- settleRun(state,catalog) -> state（55岁可主动、80岁强制）。

追加字段：phase:'event'|'planning'|'result'|'ended',activeEvent:null|{eventId,outcomes:{choiceId:outcomeId}},eventQueue:[],seenEvents:[],pending:[],lastResult:null|result, ending:null|ending, matchedEndings:[],discoveredHistory:[],storyHistory:[],dueAnchors:[],runStats。UI 通过catalog.events.find ID取全文。

catalog:{events:事件数组,families:数组,history:数组,endings:数组,characters:数组}，由root fetch，不在模块内import JSON。

内容代理负责将历史原型映射为相关敞口冲击并传core，shock:{id,title,channels,returns:{stock?:小数,bond?:小数,crypto?:小数,futures?:小数},incomeFactor?:小数}，不直接乘cash。主线触发使用crossed年龄并记入dueAnchors。剧情原型venture只结算本次新投入，不再影响旧仓。已有世界效应与新投资抽象收益分开。

历史模式按年份已有日期，先注册消息/冲击再展示，不伪造未来史实。未成年允许历史家人回忆，禁用成人投资。remix只抽6–10个历史模板、留有间隔。180节点都参与符合资格的抽样；不可只硬编码30张。
