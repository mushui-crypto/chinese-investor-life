# v1.51 健康与生活费

生活费告急改为独立生活状态卡，不再与股票交易室共用外框。原属性“身子骨”统一显示为“健康”。

## 生活费和伙食

- 每日基本伙食 ¥20，已包含在原日常开销中，不额外加收。
- 日结收入到账后，现金优先支付伙食，余款支付其他日常开销；资产必须主动变现才可支付。
- 完全缺食一天健康 −10；部分不足按 `ceil(10 × 伙食缺口 / 20)` 扣除，不超过当前健康。
- 房租等其他开销未付清只记欠款，不直接扣健康。取消原连续欠费七天的统一失败规则。
- “先安排伙食”不消耗精力，提前支付当天的基本伙食，计入当日账单，日结不重复扣款。
- 安排伙食可以中断缺食，但不会立刻回满健康；缺食状态中，休息和其他正向属性加成不能代替食物恢复健康。

## 就医与结束

| 状态 | 后果与入口 |
| --- | --- |
| 健康 >30 | 正常生活，可通过日常休息恢复 |
| 健康 ≤30 | 提示需要就医，提供“去医院”入口，快进停留 |
| 健康 ≤10 | 升级为危急提示 |
| 健康 =0 | 本局结束；连续缺食导致的死亡使用 E29，其他健康耗尽使用 E33 |

住院前显示费用、时间和工资影响。住院治疗与观察占用一个生活日，医疗费 ¥1,500，结束恢复至 60；当天医院供餐，不计工作工资，养老金照常结算。医疗现金不足计为“住院医疗欠款”，其他日常开销和持仓仍照常结算；不强制变卖资产，不免除原有债务。住院不要求剩余精力。完成后不能在健康高于 30 时重复住院。

待处理的日常事件先完成，避免事件被跳过。期末已经结清时，允许先进入下一期再就医。半年度或年度快进在可能缺食时改为按日结算，不会跳过整个求生过程。以上阈值和费用均为游戏规则。

## 布局与存档

生活状态卡显示缺口、开销、预计收入和可变现资产；伙食与健康另起一组，具体规则默认折叠。交易室保留自身边框；两张卡片之间留 16px。窄屏纵向排列，按钮保持可点击高度，长弹窗内部滚动。

旧存档只初始化缺食和住院记录，不补扣历史健康；已经完成的旧版失败档案保持原样。重复读档、打开面板不会重复收取生活费或扣健康。
